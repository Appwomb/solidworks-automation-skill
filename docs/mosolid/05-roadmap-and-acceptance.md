# 5. 路线图与验收

阶段按依赖排列，不按日历。后一阶段开始前，前一阶段的验收记录要在授权的 Windows + 正版 SolidWorks 上重跑并通过。离线 pytest 和 Fake Handler 可以并行，不能代替真机。

本环境没有 SolidWorks。本设计 PR 不声称任何阶段已经真机通过。

已有 Golden 继续有效。`mounting_bracket` 的 120×80×10、四孔 Ø7 是本仓库已经写进 `golden-workflows.yaml` 的规格。下面的 MoSolid 用例是产品验收，尺寸另选一套，避免和旧证据混在同一目录里互相覆盖。

## 5.1 阶段

### P0 设计冻结

本目录。

验收：

- 只有 `docs/mosolid/` 下的文档变更。
- 对比表里的每个真机说法能指回仓库文件或标成 E3/E0。
- AGPL 决定在文档中是“不复制”，而不是含糊的“参考并适当引用代码”。
- 老板决定表（第 6 篇）有明确的默认建议和未决项。

P0 通过不等于可以写 COM。P1 开始前，第 6 篇的 D1、D2、D3 要有书面选择。D4、D5 可以在 P5 前再定。

### P1 执行内核

交付：COM 执行进程、专用 STA、`operation_id`、`state_version`、intent 审计失败则不调用 COM、查询工具、新建空零件、一次拉伸、质量属性回读。

验收（真机）：

- 用户已打开正版 SolidWorks。执行进程只附着，不创建第二个 `SLDWORKS.exe`。
- 新建零件并拉伸一个 10×10×10 mm 方块。回读体积与 1000 mm³ 的差在 0.05 mm³ 以内，特征树含草图与凸台。
- 审计文件中，对应 `operation_id` 的 `intent` 行的时间戳早于 SolidWorks 特征创建完成，并且早于 `result` 行。测试方法：intent 的 `fsync` 完成后才发 COM；用例读取审计偏移，再允许 COM 继续。
- 把审计目录改成不可写。同一拉伸不再发生，响应码为 `AUDIT_UNAVAILABLE`，特征树与调用前一致。
- 重复同一 `operation_id` 返回 DUPLICATE，不产生第二个凸台。
- `state_version` 落后时拒绝，特征树不变。
- 查询工具在审计不可写时仍可执行。
- 离线单测覆盖队列、版本冲突和审计失败，不连接 SolidWorks。

### P2 参数化安装板

交付：完全定义草图、四孔切除、圆角、按尺寸名改板厚。优先调用本仓库已有零件与孔脚本，不平行重写。

规格（MoSolid 用例，毫米）：

| 项 | 值 |
|---|---|
| 板 | 100 × 60，厚度驱动尺寸 `thickness` 初值 8 |
| 孔 | 4 × Ø6.6 贯穿，中心距板边 12，即中心 (±38, ±18) |
| 圆角 | 四角 R3，草图圆角或边圆角均可，但必须是可回读的特征 |
| 改尺寸 | 把 `thickness` 改为 12 |
| 材料 | 显式设置并回读。未设置成功则质量为“未验证”，用例失败 |

验收：

- 改厚之前：体积 = (100×60×8 − 4×π×3.3²×8) mm³，容差 0.05 mm³。四孔为贯穿：每个孔两个圆边，轴向长度等于当时板厚。
- 改厚之后：同一公式用 8 换成 12。孔仍贯穿，位置不变。特征树仍含原来的凸台、切除和圆角，不出现第二块板。
- 四个 R3 可回读。欠定义草图失败。
- 错误参数：孔中心放到板外、直径为 0、厚度为负。COM 不创建新特征，或创建失败后回读证明文档与调用前指纹一致。返回 `invalid_argument` 或 `verification_failed`，不能是完成。
- 文档切换：先打开用户指定的另一个空零件并激活，再发安装板的拉伸。操作因文档身份不一致失败，用户那个零件的特征树不变，安装板文档也不被偷偷激活后改写。用例要分别断言两个文档。

### P3 两件装配与干涉

交付：第二块板（同规格，文件独立）、装配、配合、干涉检查。

规格：

- 两块 P2 最终状态的板（厚度 12）。
- 装配中第一块固定在原点。
- 第二块与第一块共面贴合后，沿板法向分开 10 mm（距离配合或等价的完全定义配合）。预期两板间隙 10 mm，无干涉。
- 另有一步把距离改为 0，预期干涉体积大于 0；然后恢复到 10 mm。这一步证明干涉工具不是恒返回“无干涉”。

验收：

- 回读两个实例的源路径、固定/浮动、变换。距离配合的驱动值回读为 10 mm，容差 0.01 mm。
- 10 mm 时间隙无干涉；0 mm 时有干涉；恢复后再次无干涉。
- 配合数量与类型与规格一致。多出来的配合使用例失败。
- 拒绝审批：对“把距离改为 0”的 R2 确认选拒绝。审计为 `denied`，配合值仍为 10 mm，干涉结果保持无干涉。

### P4 工程图与 STEP

交付：零件工程图、装配工程图或至少一张包含两块板的工程图、STEP。

验收：

- 保存 `SLDPRT`、`SLDASM`、`SLDDRW`。关闭后按路径重开，特征树、配合和关键尺寸仍在。
- 工程图含板的外形尺寸、厚度、孔径和孔定位。PDF 导出后能提取这些数字。图框和 GB/T 外观若未在本阶段单独立项，结论保持 `review_required`，不把“有 PDF”写成“图纸合格”。
- STEP 非空，SHA-256 记入本轮台账。用无头内核读回装配包围盒：两块 12 mm 板沿法向净距 10 mm 时，该方向总尺寸为 34 mm，容差 0.05 mm。无头读回只作旁证。
- 台账拒绝把运行开始前已经存在的同名 STEP 当作本轮产物。
- 到此，P2+P3+P4 作为一条连续脚本跑完，中间不人工改模型。这是相对单个参考项目的完整性门槛：同一条自动化路径覆盖零件、改尺寸、装配、干涉、工程图和 STEP，并且每步有回读。

### P5 桌面壳与审批

前提：D4 已决定；若选与 MoAspen 共用，则 MoAspen 已可读且差表已合并。

验收：

- Tauri 窗口里能发起 P4 那条脚本的交互版：R1 在会话开始确认一次；R3 导出覆盖要逐次确认。
- 模型配置可在 Anthropic 兼容与 OpenAI 兼容之间切换，密钥不出现在审计和界面截图里。
- 拒绝、批准过期、参数变化后的旧批准，都不会执行。
- 不启动 Electron，不把 Millwright 做成第二个产品。

### P6 特征 IR

前提：P4 连续脚本稳定。IR 从这块安装板反推，而不是从 SolidPilot schema 翻译。

验收：

- 编译器无模型。同一 IR 与同一起始版本得到同一工具序列。离线用假执行端口测。
- 真机：IR 重建出的板，体积、孔位、圆角与 P2 手算一致。
- 把厚度从 8 改为 12 后，孔的引用仍能解析，或显式失败并要求重新查询。静默打到错误的边上，用例失败。
- 仓库 diff 中没有 `mcp-server-solidworks` 的文件。

### P7 故障与发布门禁

把第 5.2 节的故障用例全部放进同一台正版 SolidWorks 的发布脚本。P7 通过前，不把 MoSolid 描述成已经比每个参考项目都更可靠。完整性在 P4 证明，可靠性在 P7 证明。

## 5.2 真机总验收用例

环境：

- Windows 10 或 11，64 位。
- 正版 SolidWorks。第一轮指定 2026，因为本仓库 Golden 与 hjbaard、python README 的声称都指向 2026。2024 作为第二轮：本仓库 `assembly_and_mates` 的清单版本目前只写了 2024，两轮都要有记录，不能用一轮代替另一轮。
- Python 版本与本仓库要求一致（3.10+，现有真机记录使用 3.12）。
- 开始前枚举 `SLDWORKS.exe`。若已有用户实例，发布脚本记录 BLOCKED 并退出，不杀进程。空机再跑。
- 输出目录必须不存在，拒绝覆盖。

主路径（必须一次跑完）：

1. 附着。回读版本字符串。
2. 按 P2 规格建板、四孔、圆角。回读尺寸、体积、质量、特征树。
3. 改厚度到 12 mm。再次回读。孔位不变。
4. 第二块板，同样规格，独立文件。
5. 装配，固定第一块，第二块法向距离 10 mm。回读配合与变换。干涉为空。
6. 工程图标出外形、厚度、孔径、孔定位。保存并重开。
7. 导出 STEP 与 PDF。台账记录哈希。无头旁证包围盒。PDF 含关键数字。

故障路径（每条单独的 run，从干净会话开始；能并进主路径且不污染结果的，可以接在主路径之后，但断言要分开）：

| 编号 | 操作 | 通过标准 |
|---|---|---|
| F1 | 错误参数：板外孔、零直径、负厚度 | 无新的成功特征；状态不是完成；审计没有 `result=ok` |
| F2 | 文档切换 | 非目标文档与目标文档的特征树都符合“只有目标在被允许时才变化” |
| F3 | 弹窗 | 在 STA 调用期间制造一个模态对话框（或使用会弹窗的未抑制首选项）。调用在超时内返回 `user_action_required`。不发送 `WM_CLOSE`。用户关掉对话框后，后续查询仍可用。SolidWorks 进程仍在 |
| F4 | 拒绝审批 | R2 或 R3 选拒绝。`phase=denied`。几何、配合、文件与拒绝前的哈希或特征指纹一致 |
| F5 | 断线 | 在一次成功写入后断开 COM（结束执行进程，不杀 SolidWorks，或模拟 `RPC_E_DISCONNECTED`）。自动重试次数为 0。重新附着后的第一次变更在指纹核对前被拒绝。核对一致后才允许下一步。不允许出现两个相同凸台 |
| F6 | 日志失败 | intent 阶段目录不可写：COM 不发生。result 阶段在 COM 已返回后使追加失败：状态为 BLOCKED，下一次变更被拒绝，直到人确认当前文档指纹 |
| F7 | 旧文件 | 运行前放置同名 STEP。交付门禁拒绝把它当作本轮产物 |
| F8 | 重复 operation_id | 不产生第二个特征 |
| F9 | 落后的 state_version | 不执行 |
| F10 | 欠定义草图 | 该步失败 |

每条真机 run 的证据目录至少包括：

- SolidWorks 版本、进程启动方式（附着而非新建）。
- `mcp_audit.jsonl` 全文。
- 特征树、尺寸、质量属性、配合、干涉的 JSON。
- 产物相对路径与 SHA-256。
- 最终状态：完成、复核、阻塞或失败。主路径只有在回读全部通过且 F 类没有被跳过的发布矩阵里，才能标完成。单跑主路径时，工程图目视项可以是 `review_required`，此时总状态不是“无人值守完成”。

## 5.3 离线必须一直绿的部分

- 能力清单与 MCP schema 一致。
- 审计门：不可写则变更函数不被调用。用假 COM 端口。
- 恢复决策：未知错误不重试变更。
- IR 编译器（P6 之后）：假端口，无 SolidWorks。
- 现有 Execution Core eval 仍通过。若审计门改变了 Core 的 Trace 失败语义，视为回归，不合并。

默认 CI 不安装 SolidWorks。真机脚本用显式环境变量收集，避免在 Ubuntu runner 上假装跳过即成功。发布说明里分开写“离线通过”和“哪一台 SolidWorks 的哪一次 run 通过”。
